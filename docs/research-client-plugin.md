## 0. 结论速览

- **识别为 bundle(profile 补丁层)** 的唯一硬条件:package.json 有 `"dsh": {"bundle": {"patch": "./cordis.patch.yml"}}`(判定代码 `DSH/lib/plugin-9h8shc4d.js:32`,缺失即 fail-loud 于 `dsh-app-boot/lib/index.js:548-549`),且该包已装入 profile 依赖并列入 `package.json` 的 `dsh.profile.bundles`(`DSH/lib/plugin-9h8shc4d.js:46-78` 的 reconcile 会自动追加;`dsh plugin --profile web add <pkg>` 触发)。
- **识别为 client 模块(浏览器端)** 由 `@deepseek-ai/dsh-client-modules` 对每个已挂载 loader entry 扫描其包 manifest 完成,必需字段:`dsh.client.platform: "web"` + `exports["./client"]` 指向**已存在**的构建产物(`window.__ModuleLoader__.load({id,factory})` 格式经典脚本);可选 `inject: string[]`、`immediately: boolean`。
- **送达方式**:纯静态托管、零服务端 transform。Node 半按内容 sha1 短哈希构图,路由 `GET /plugins/<entry-name>/client.js?rev=<hash>` 直接 `readFile` 磁盘上的产物,no-cache 头;并把 boot 图注入 `window.__DSH_BOOT__`。改了磁盘上的 `lib/client.js` 后,浏览器刷新页面即取新代码(见 §4)。
- **宿主插座的挂载行**:由包自带 `cordis.patch.yml` 的 `- insert: [{id, name}]` 声明,`name` 是 Node 可解析的模块说明符。**对客户端插件,name 必须能同时过两关**:Loader.import(原生 ESM,目录路径会 `ERR_UNSUPPORTED_DIR_IMPORT`)和扫描器的 `require.resolve(name + "/package.json")` → 因此实际可行形态是「装进 profile node_modules 的裸包名」;绝对路径带文件名的写法(如 `~/.dsh/plugins/session-title-rule/index.mjs`)只适用于纯 host 插件。

## 2. 问题二:JS 从哪里来、怎么送达浏览器

### 2.1 全链路(全部为预构建产物的静态托管)

1. **shell 本体**:`@deepseek-ai/dsh-web-frontend/dist`(Vite 产物),由 `dsh-host-frontend-static`(config `{distIndex}`,占用 webserver 唯一 fallback 座位,miss 回落 index.html SPA 路由,README 全文有述)直读文件服务;**没有任何服务端 transform/vite dev server 参与**。
2. **插件 client bundle**:`dsh-client-modules` 的 node 半(src/index.ts 注释 :9-12 与实现):
   - 监听 `ctx.on("internal/plugin")`,把每个非禁用 entry 的 `options.name` 入脏集,微任务 flush(`lib/index.js:138-162`);
   - 对每个名字 `require.resolve(\`${spec}/package.json\`)`(以 `ctx.baseUrl`= **profile 目录**为锚,L139),解析出包根;若 `dsh.client.platform === "web"` 且 `exports["./client"]` 存在,得到 `clientPath = join(dirname(pkgPath), clientRel)`(L248-257);
   - 读文件算 sha1 前 12 位作为 `rev`(:86-93),生成图行 `{ id: "<name>", url: "/plugins/<id>/client.js?rev=<rev>", inject?, immediately? }`(:91-99);
   - 经 `ctx.webServer.tapIndex(injectBootManifest(html, composed))` 把整张图注入每个 index.html 的 `window.__DSH_BOOT__`(:160-164);自身注册 `/plugins` prefix 路由(:161-162)。
3. **HTTP 出口**:`serveBundle`(`lib/index.js:313-344`)= URL 解析到表中的 `clientPath` 后直接 `readFile`,`content-type: text/javascript`、`Cache-Control: no-cache`;`.js.map` 同理。**没有 hash 校验拦截,服务的是磁盘当下内容**。
4. **浏览器端**(内核 = `@deepseek-ai/dsh-client-web`,两级引导):先建空模块表 → 按 `__DSH_BOOT__` 图行逐个 `loader.create({name:"<id>"})`;`<script>` 加载 `/plugins/<id>/client.js` 仅执行 `window.__ModuleLoader__.load({ id, factory })` 注册懒 CJS 工厂,`EntryTree.import("<id>")` 时才物化(factory(require);README「Lazy CJS model (web2)」段,`dsh-client-modules/README.md`)。安全性:URL→磁盘文件是查表(`this.table`)非路径拼接,无目录穿越风险。

### 2.2 本地磁盘任意路径能否直接作客户端模块 —— 边界结论

宿主侧加载走 `Loader.import`(`@deepseek-ai/cordis-plugin-loader/lib/index.js:260-273`):`cordis:` 内建 → internal 解析器(HMR 服务需要 `--expose-internals`;DSH bin/boot 中未见该 flag)→ 其余交**原生 `import()`**。实测 `import('/Users/cat')` → `ERR_UNSUPPORTED_DIR_IMPORT`,即**目录路径不能当 `name`**。

而 client 扫描器要求 `resolve(name + "/package.json")` 成功,故**带扩展名的文件路径也不行**(如 session-title-rule 那种写法)。

- **真实先例(可行的「路径系」写法)**:仅限纯 host 插件——`DSH/node_modules/@deepseek-ai/dsh-base/cordis.patch.yml:46-59`:
  ```yaml
  # LOCAL OVERRIDE (session-title-rule): replaces the official first-prompt
  # LLM titler with ~/.dsh/plugins/session-title-rule …
  - id: session-title-rule
    name: /Users/cat/.dsh/plugins/session-title-rule/index.mjs
  ```
  该插件没有 package.json/`dsh.client`,不进浏览器图,所以不受扫描器约束。
- profile 自有 patch 里也有路径无关先例:`~/.dsh/profiles/web/cordis.patch.yml:18-35` 用 `- insert: [{id: mcp-qwen-mm-plugins-core, name: '@deepseek-ai/dsh-mcp-client', config:{…}}]` 挂 MCP 客户端(npm 包名 + config 全文)——证明「仅靠一段 patch 行即可让一个包进组合」。
- **`file:` 协议依赖全树 0 命中**(grep 全 node_modules package.json),无既有范式。

⇒ **客户端插件的 JS 必须以「一个可以被 `<spec>/package.json` 解析到的包」的形态存在**,即位于 profile 能解析的 node_modules 下(真装或 symlink);`~/.dsh/plugins/xxx` 本身不是解析根。变通:B 方案——手工 symlink 进 `~/.dsh/profiles/web/node_modules/`,即可绕开 pnpm/dependencies/think-flow 先例即如此(ls 显示 `dsh-think-flow-flow -> ../../../../dsh-think-flow-flow`,孤链,lockfile 0 记录,仍曾被解析挂载)。

> **更正(/tmp/research-q2-delivery.md 的过度乐观结论)**:该子报告称「insert 行 name 指向本地目录(含 dsh.client 声明)即可自动进 boot 图并被浏览器加载」。其引用的扫描器腿(`require.resolve("<dir>/package.json")` 对绝对目录确实可解析)无误,但**宿主腿必失败**:`Loader.import` 走原生 ESM,Node 对目录导入直接抛 `ERR_UNSUPPORTED_DIR_IMPORT`(本机两次实测),entry 无 fiber → `processOne` 的 `entry.fiber !== void 0` 检查不过 → 不进图、不服务。仅 q2 报告单独阅读会误导,以本节为准。

## 4. 问题四:最小可行配方

### 通用:任何客户端插件都需要的东西

```text
my-panel/
├── package.json
└── lib/
    ├── index.js     # host 半边:export function apply(){} 即可(fiber 必须活,扫描器才看它)
    └── client.js    # window.__ModuleLoader__.load({ id:"my-panel", factory:(require)=>{ ... } })
```

`package.json` 最小骨架(three-proven 形态):
```jsonc
{
  "name": "dsh-my-panel",              // 建议 scoped:@you/dsh-my-panel,避免撞名
  "version": "0.0.1",
  "type": "module",
  "main": "lib/index.js",
  "exports": {
    ".": "./lib/index.js",
    "./client": "./lib/client.js",
    "./package.json": "./package.json"
  },
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": {
      "platform": "web",
      "inject": ["@deepseek-ai/dsh-client-runtime"]   // 按需;默认 [] 也合法
    }
  }
}
```
随手在包根放一份 `cordis.patch.yml`:
```yaml
- insert:
    - id: my-panel
      name: dsh-my-panel
```

### 路线 A(正式,recommended 默认):装成 profile 依赖 + 进 bundles

1. 建工程、构建产出 lib/(esbuild/tsdown 均可,关键是两种产物格式如上);
2. `cd ~/.dsh/profiles/web && pnpm add <registry-name 或 本地路径>`(等价 file: 协议效果;本机从未出现过字面 `file:`,pnpm 写的是相对路径 spec,同样成立);或直接 `dsh plugin --profile web add "$(pwd)"`;
3. 确认 `profiles/web/package.json` 的 `dsh.profile.bundles` 数组里有该包名(reconcile 会自动加;手装则自己补一行);
4. 重启 web profile(pnpm install 改动文件系统后重启最稳)。

**代价**:动 pnpm-lock.yaml;升级/重装 profile 依赖时安全可持续;一次安装永久生效。第三方三件套(linxin666 / ychris12138 / 已卸的 think-flow)全是这条路。

### 路线 B(零安装,symlink 版,本轮验证过的先例可循)

1. 工程直接放 `~/.dsh/plugins/my-panel/`(照上面结构建好);
2. `ln -s ~/.dsh/plugins/my-panel ~/.dsh/profiles/web/node_modules/my-panel`(一个 symlink,不碰 dependencies/bundles/pnpm-lock);
3. 在 `~/.dsh/profiles/web/cordis.patch.yml`(用户 patch 层,profile 启动时被 watchUserPatches 实时 watch,改动热生效)追加:
   ```yaml
   - insert:
       - id: my-panel
         name: my-panel          # 裸包名;symlink 保证它可解析
   ```
4. 不重启也可能即时挂载(patch 热更新 watch,L254-270);保守起见重启一次 web profile。

**代价/风险**:下一次在该 profile 跑 `pnpm install` 可能 prune 掉外来 symlink,需要重打;非官方 reconcile 流程,属灰色但已被 think-flow 实证可行。

### 明确不可行/只适合特定场景

- **`name` 写绝对目录路径**:/plugins 扫描器 `require.resolve(spec+"/package.json")` 能过,但 Loader.import 原生 ESM 分支报 `ERR_UNSUPPORTED_DIR_IMPORT` → 宿主半边起不来 → entry 无 fiber → 客户端 bundle 也不会被服务。不可行。
- **`name` 写绝对文件路径(index.mjs 式)**:仅适用于无浏览器半边的纯 host 插件(session-title-rule 先例,dsh-base/cordis.patch.yml:52-59);扫描器解析不到 `<file>/package.json`,不会出现在浏览器图中。

### 浏览器何时拿到新代码(不开 dev:watch)

- **传输链路本身是「读盘直服 + no-cache」**:只要文件变了并且图谱里的 `rev` 与路由不再严格校验……——兜底事实链:`serveBundle` 每次请求都重新 readFile(L330-338),响应带 `no-cache`;HMR 图谱刷新靠 node 半 stat-poll(500ms 默认,@deepseek-ai/dsh-client-hmr/lib/index.js L107 setInterval),但它只是推浏览器主动重载用的优化,**不做访问开关**。
- **实践操作**:改完 src → 重跑你自己的构建(如 esbuild … --outfile=lib/client.js)→ 浏览器 Cmd+R 硬刷新。无需重启 dsh。偶发「刷新后还是旧的」时,重启 web profile 让扫描器重新计算 rev 即可(rebuilt():L188-208;失配场景 README short.html 有描述)。
- **想全自动**?可选启动你自己的 builder --watch:node 半的 poll 检测到 lib/client.js 变化并通过 SSE `/plugins/events` 通知浏览器自动 reload(client-hmr 机制;基座常驻,`dsh-web-app/cordis.patch.yml` 内 `client-hmr` 行未被禁用)。这不是必须步骤,只是升级体验的可选项。

## 5. 推荐(一行)

**最小摩擦且被三个真实插件验证过的做法:在 `~/.dsh/plugins/my-panel/` 下放标准双半边包(package.json 带 dsh.bundle.patch + exports["./client"],patch 行 `- insert:[{id, name:"my-panel"}]`),把它 symlink 进 `~/.dsh/profiles/web/node_modules/`,然后在 `~/.dsh/profiles/web/cordis.patch.yml` 用户层加那段 insert 并重启一次 web profile;此后每次改代码只需重跑自己的 esbuild 并硬刷新浏览器。**
