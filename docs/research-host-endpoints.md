## TL;DR(先读这段)

浏览器可查/可写一个 host 服务,**唯一官方机制是 Typert Gateway RPC**:

```
浏览器:  POST {origin}/api/<namespace>/<method>
请求体:  {"type":"client-request","rpcId":"<uuid>","method":"<namespace>/<method>","payload":{"args":{...wire字段}}}
响应体:  {"type":"server-response","rpcId":"<同上>","result":{"ok":true,"value":{...}} | {"ok":false,"error":{code,message,details}}}
```

- 路由前缀 `/api` 由 **@deepseek-ai/dsh-client-connection**(node 半面)注册到 webServer;
- **@deepseek-ai/dsh-api-gateway**(`typertGateway` 服务)拦截其中「被 Typert 描述符声明」的两段式端点并分发到 Cordis Service 实例;
- 未被拦截的 `/api/<domain>.<verb>`(点号方法名)落到 **@deepseek-ai/dsh-host-apiproxy**(`apiProxy`,固定 BFF 方法表,不可由用户插件扩展);
- 无 token/CSRF:靠 Host 回环围栏 + Origin/Sec-Fetch-Site 同源检查 + 可选 LAN `trustedHosts` 白名单。
- 另一条官方通路:goal 这类领域还通过 **session 事件流(WebSocket/SSE `/api/events.mux`)复制投影**到浏览器供 UI 只读展示(UI 不轮询 HTTP)。

## 1. 标准做法:以 @deepseek-ai/dsh-goal 为解剖样本

### 1.1 组成件(三种 face)

| 文件 | 角色 |
|---|---|
| `dsh-goal/lib/index.js` | 宿主服务本体:`GoalService extends TypertRemoteService`,`super(ctx,"goals")` 注册为 Cordis 服务 `goals` |
| `dsh-goal/lib/typert.host.js` | **生成物**(头注释 `Generated by @deepseek-ai/dsh-typert-generator from FaceModel`):导出 `TYPERT = {package,face:'host',schemas,invocations,model}`——宿主侧严格描述符 |
| `dsh-goal/lib/typert.remote-client.js` | **生成物**:导出 `TYPERT_REMOTE = {package,descriptors:[...]}`——浏览器侧消费的同一批描述符 |

包导出声明(`dsh-goal/package.json:22-33`):
```json
"./typert":  { "default": "./lib/typert.host.js" },
"./remote":  { "default": "./lib/typert.remote-client.js" }
```
`./typert` 这个导出名是自动发现钩子(见 §2.4 typert-loader)。

### 1.2 服务上的发布约定:不是 remote/query/command 前缀,而是 `@Remote('方法名')` 装饰器

`lib/index.js:430-438`(编译产物中的装饰器数组):
```js
return class GoalService extends _classSuper {   // _classSuper = TypertRemoteService
    static {
        _edit_decorators  = [Remote("edit")];
        _pause_decorators = [Remote("pause")];
        _resume_decorators= [Remote("resume")];
        _complete_decorators = [Remote("complete")];
        _clear_decorators = [Remote("clear")];
        _remoteExportCreate_decorators = [Remote("create")];  // 方法名叫 remoteExportCreate,wire 名叫 create
```
- 服务键与 wire 命名空间合一:`super(ctx, "goals")`(lib/index.js:517)。命名空间也可用 `bindTypertRemote(service,key,{namespace})` 单独指定(dsh-typert-protocol/lib/index.js:42-51)。
- 端点 = `<namespace>/<method>` 两段(dsh-api-gateway/lib/index.js:279-281 `endpointOf`;typert-registry/lib/index.js:62-67)。segment 字符白名单 `/^[A-Za-z0-9_$.-]+$/`(dsh-typert-protocol/lib/index.js:8,14-16)。
- 只有带 `@Remote` 标记的方法才跨边界:`get/disarm/block` 没有装饰器,因此不在 invocations 列表里(typert.host.js:114-366 共 clear/complete/create/edit/pause/resume 六个)。
- `@Remote('别名')` 支持 wire 名 ≠ 实现名(goal 用 `remoteExportCreate` 导出为 `create`,typert.host.js:196-201 `"implementation":"remoteExportCreate"`;运行期分发走 `descriptor.implementation ?? descriptor.method`,api-gateway/lib/index.js:101-102)。
- 底层标记状态机:dsh-typert-protocol/lib/index.js:53-66 `TypertRemoteService`(构造时挂 `this.typertRemote = bindTypertRemote(this,this.name)`);67-76 `Remote()`;99-106 `remoteMethods(service)` 读私有 WeakMap。Gateway 的 SRC 回退扫描正是消费这两者(§2.2)。

### 1.3 参数/接收方:lookup 与 json 两类 wire 参数

生成的描述符样例(`lib/typert.host.js:114-154`,原文节选):
```js
invocations: [
  {
    id: '@deepseek-ai/dsh-goal#goals/clear',
    service: 'goals',
    namespace: 'goals',
    method: 'clear',
    invocation: { kind: 'direct' },          // direct=从宿主根 ctx 取 receiver;'context'=由 Context provider 解析
    scope: { context: 'agent', wire: 'agentId' },  // 浏览器首参即身份(单 lookup 参数投影)
    parameters: [
      { name: 'agent', wire: 'agentId', source: 'lookup', lookup: 'agent',
        codec: { mode: 'strict', typeSymbol: '@deepseek-ai/dsh-session/types#SessionId', schema: <zod> } },
      { name: 'ref',   wire: 'ref',    source: 'json',
        codec: { mode: 'strict', typeSymbol: '@deepseek-ai/dsh-goal/client#GoalRef', schema: <zod> } },
    ],
    result: { mode: 'strict', ... },
  },
```
- `source:'lookup'` 的参数不占业务实参——宿主用它把 wire 身份(如 sessionId)解析成 Agent 对象;provider 在 api-remotes 配置(§2.3)。
- `source:'json'` 的参数按 wire 字段名进 payload.args,浏览器只传 JSON。
- 解析后的 receiver 就是 `ctx.get(descriptor.service)` 返回的 Service 实例(api-gateway/lib/index.js:96-97),随后 `validateBinding` 强制实例携带一致的 `typertRemote` 绑定(:98, :282-294)。
- 支持尾参 `signal` 取消(strict 描述符要求 `cancellation.parameter === 'signal'`,typert-loader/lib/index.js:187-189;网关注入 `request.signal`,api-gateway/lib/index.js:100)。

### 1.4 序列化契约:JSON-safe 强制 + zod 严检

dsh-api-gateway/lib/index.js:342-356 `decode()`:strict 时先 `codec.schema.parse(value)`,再过 `assertJsonValue`(:357-386):只接受 null/string/bool/有限 number/plain object/稠密 array;拒绝 Symbol 属性、循环、getter、稀疏数组。结果若 strict 则不能返回 `undefined`(:111-112)。=> 服务方法「返回值就是普通 JSON 对象」,Date/Map/class 实例都会被拒。

### 1.5 注册链

- `dsh-base/cordis.patch.yml:30-37`:`typert`→dsh-typert-registry、`typert-loader`→dsh-typert-loader、`typert-gateway`→**@deepseek-ai/dsh-api-gateway**;`:262-263` `goal`→@deepseek-ai/dsh-goal(default export 即 GoalService 类,cordis 加载器直接当构造器用,见 cordis-plugin-loader/lib/index.js:738 `exports.default ?? exports`)。
- 目标域还包括只读投影给会话流:`lib/index.js:522-531` `ctx.inject(["sessionProjections"], …projectionCtx.sessionProjections.register({key:"goal",…}))`;UI 由此读取(§3.3)。

README.zh.md 第 20 行也印证:「服务通过 goal.md 的生成区块公开 create、edit、pause、resume、complete、block 和 clear 动词」——动词集就是生成描述符里的六个 `@Remote`。

## 2. api-gateway vs api-remotes vs host-apiproxy 三者职责

### 2.1 传输层:@deepseek-ai/dsh-client-connection(node 半面)

`lib/index.js:469-480`:`name="client-connection"`,`inject=["webServer"]`。
真正的路由注册样例(lib/index.js:550-559):
```js
const route = { kind: "prefix", path: API_PATH /* "/api" */, handler: async (req,res)=>{
    if (!isTrustedApiRequest(req, trustedHosts)) { res.writeHead(403); res.end("forbidden"); return; }
    await bridge(req, res, fetchHandler, maxRequestBodyBytes);
}};
ctx.effect(() => ctx.webServer.register(route), "client-connection: /api route");
```
- 共享 fetch 处理器(:535-549):先看该方法是否被 **interceptor(即 typertGateway)** 认领,否则 fallback 到 `ctx.get("apiProxy")`;GET `/api/events.mux`/`/api/events.host` 引导升级 WebSocket(:539-545,:566-587 `registerUpgrade`)。
- 权限模型(:107-198 `isTrustedApiRequest`):**无 token**。① Host 头必须是回环(`localhost/[::1]/127.x`,:100-104)或配置的 `trustedHosts` bare authority;② `sec-fetch-site: cross-site` 直接拒;③ 带 Origin 时必须同源。注释明说这是 DNS-rebinding/CSRF 围栏而**非认证层**(:113-119)。配置来自 web 行(web-app/cordis.patch.yml:156-163,`trustedHosts: !!js ctx.webRuntime.trustedHosts`,由 LAN bind 推导)。
- 特权子集钉死回环:lib/index.js:504-520 `PRIVILEGED_METHODS`(agentPreset.read、settings.update、credentials.set、host.openPath 等),:537-538 即使通过了 LAN 白名单也要再过空白名单检查。
- 信封协议(:275-301 `rpcFetchHandler`):仅 `POST`+`application/json`;体必须过 `clientRequestSchema`(自 @deepseek-ai/dsh-host-apiproxy/api);`message.method` 必须等于 URL 尾段;响应 `{"type":"server-response",rpcId,result}`(:322-329)。
- 其他真实路由注册参考:GET 下行 `/api/events.mux`/`events.host` = WebSocket upgrade(client-connection:569-587)、`/plugins/*` 静态 client bundle 前缀路由(dsh-client-modules/lib/index.js:160-166)、SPA dist 占 fallback 席位(web-app 注释,dsh-web-app/cordis.patch.yml:127-134)。

## 3. 浏览器侧如何消费

### 3.1 传输原语(fetch 封装真身)

dsh-client-connection/lib/client.js(browser bundle,:10088-10112,原文):
```js
function createWebConnectionRpc() {
    return { async call(channel, endpoint, payload, signal) {
        const rpcId = RpcId(randomUuid());
        const message = { type: "client-request", rpcId, method: endpoint, payload };
        const response = await globalThis.fetch(new URL(`${channel}/${endpoint}`, resolveBase()), {
            method: "POST", headers: { "content-type": "application/json" },
            body: JSON.stringify(message), ...signal === void 0 ? {} : { signal } });
        if (!response.ok) throw new Error(`transport failure for ${channel}/${endpoint}: HTTP ${response.status}`);
        const full = serverResponseSchema.parse(await response.json());
        if (full.rpcId !== rpcId) throw new Error(`rpcId mismatch for ${endpoint}: sent ${rpcId}, got ${full.rpcId}`);
        return full.result;      // {ok,value} | {ok,error}
    } };
}
```
`resolveBase()`=页面 origin;连接插件把它作为 `ctx.connection.rpc` 提供(client.js apply,:10160 附近 `ctx.provide("connection", handle)`)。旧式 BFF 客户端同理:`callUnary` 拼 `postJson(\`/api/${method}\`, message)`(:6209-6230),SSE 用 streaming fetch 读 `\n\n` 帧(:6232-6240)。

## 4. 给 git-merge-lock 插件的最小实现配方

目标:`~/.dsh/plugins/git-merge-lock/index.mjs`(沿用 session-title-rule 的 `export const name/inject/apply(ctx,config)` 形态),新增两个浏览器可调端点:

```
POST /api/gitMergeLock/queryMergeStatus     args:{projectPath}
POST /api/gitMergeLock/saveProtectedBranches args:{projectPath, branches:[string]}
```

### 4.1 形状 A(推荐,最少机制;entry 保持 index.mjs 文件形式)

关键事实:网关对 strict 描述符仍要求 receiver 有可见 `typertRemote` 绑定(api-gateway/lib/index.js:98,282-294),绑定量产函数是公开导出的;手工 `ctx.typert.register()` 是文档化用法(typert-loader 注释 §2.4);不需要生成器、不需要 decorators、**patch 行不用加任何额外字段**(我们自己完成 typert-loader 本来做的事)。

`~/.dsh/plugins/git-merge-lock/index.mjs` 骨架:
```js
import { Service } from '@deepseek-ai/cordis'
import { bindTypertRemote } from '@deepseek-ai/dsh-typert-protocol'
import { z } from 'zod'
// 注意:与 session-title-rule 相同做法,在其目录下 node_modules/@deepseek-ai/ 里放符号链接:
//   cordis -> <DSH>/node_modules/@deepseek-ai/cordis
//   dsh-typert-protocol -> <DSH>/node_modules/@deepseek-ai/dsh-typert-protocol
// 以及 zod(zod -> <DSH>/node_modules/zod)

class GitMergeLockService extends Service {
  constructor(ctx) {
    super(ctx, 'gitMergeLock')                                  // 服务键 = wire 命名空间
    this.typertRemote = bindTypertRemote(this, this.name)       // 网关 validateBinding 必需
  }
  async queryMergeStatus(projectPath) {
    // 任意实现;返回值必须是 JSON-safe 平面对象(§1.4)
    return { projectPath, locked: false, holder: null, protectedBranches: ['main'] }
  }
  async saveProtectedBranches(projectPath, branches) {
    if (!Array.isArray(branches)) throw new Error('branches must be an array')  // 折叠成 code:'internal'
    return { saved: branches.length }
  }
}

export const name = 'git-merge-lock'
export const inject = []                                        // typert 服务由 dsh-base 常驻注入表保证先起
export function apply(ctx) {
  new GitMergeLockService(ctx)
  const zs = (s) => ({ mode: 'strict', typeSymbol: `git-merge-lock#${s}`, schema: s === 'ProjectPath' ? z.string()
                       : s === 'Branches' ? z.array(z.string().min(1))
                       : z.object({ projectPath: z.string(), locked: z.boolean(), holder: z.string().nullable(),
                                    protectedBranches: z.array(z.string()) }) })
  ctx.typert?.register?.({
    package: 'git-merge-lock', face: 'host', schemas: [],
    invocations: [
      { id: 'git-merge-lock#gitMergeLock/queryMergeStatus', service: 'gitMergeLock', namespace: 'gitMergeLock',
        method: 'queryMergeStatus', invocation: { kind: 'direct' },
        parameters: [{ name: 'projectPath', wire: 'projectPath', source: 'json', codec: zs('ProjectPath') }],
        result: { mode: 'strict', typeSymbol: 'git-merge-lock#MergeStatus', schema: zs('MergeStatus') } },
      { id: 'git-merge-lock#gitMergeLock/saveProtectedBranches', service: 'gitMergeLock', namespace: 'gitMergeLock',
        method: 'saveProtectedBranches', invocation: { kind: 'direct' },
        parameters: [{ name: 'projectPath', wire: 'projectPath', source: 'json', codec: zs('ProjectPath') },
                     { name: 'branches',     wire: 'branches',     source: 'json', codec: zs('Branches') }],
        result: { mode: 'strict', typeSymbol: 'git-merge-lock#SaveResult',
                  schema: z.object({ saved: z.number() }) } },
    ],
    model: { services: [], events: [], objects: [] },
  })
}
```
注意:
- 若担心未来 cordis 注入顺序/`ctx.typert` 缺失,把 register 放进 `ctx.inject(['typert'], (t)=> t.typert.register({...}))` 更稳(registry 的 `register()` 见 typert-registry/lib/index.js:370-380,398-420)。
- 手工路径不经 typert-loader 校验,zod 以外的 `{parse(v){return v}}` 也可跑,但请保持 zod 以获得两侧一致校验。
- patch 行(dsh-base/cordis.patch.yml 或 profile overlay)只需常规两行,无需 typert 相关字段:
  ```yaml
  - id: git-merge-lock
    name: /Users/cat/.dsh/plugins/git-merge-lock/index.mjs
  ```
- 若想把 ctx.tools.register 的模型工具挂在同一个 apply 里,与本端点共存没有冲突(工具面和 wire 面独立)。

## 已确认 vs 存疑点

**已确认(静态代码证据,均有路径+行号)**:信封协议与 /api 路由注册(connection lib/index.js:550-559、client.js:10088-10112);网关认领/分发/SRC 回退(api-gateway lib/index.js:61-63,92-135,142-212);lookup/json 参数与 JSON-safe 结果契约(api-gateway :233-255,342-386);goal 装饰器发布与生成物(dsh-goal lib/index.js:430-438、typert.host.js);api-remotes 的 lookup/Context provider 配置(index.js:155-164)与五面 TYPERT_REMOTE 挂载(client.js:5917-5923);ui-goal 的 `ctx.remote.goals.*` 消费(client.js:371-436);投影读通道(sessionProjections + faceOf('goal'));typert-loader 注释明示手工 `ctx.typert.register()` 为合法途径(lib/index.js:27-29),registry `register()` 键为 `<ns>/<method>`(index.js:398-420);apiproxy 方法表硬编码不可扩展。

**存疑(未实机验证)**:
1. 目录形 entry(`dsh.client` 双面声明 → 浏览器 `remote.$mount` 自定义描述符):扫描语义已从 dsh-client-modules/lib/index.js(:60-70,:115-262)确认,但 cordis-plugin-loader 对目录形 plugin 行是否原样 import 其 package.json 入口未运行验证——采用前先冒烟。
2. 手工 register 示例中的 zod schema 组合按 strict 校验规则构造(typert-loader/lib/index.js:206-211 要求 zod v4 实例、`mode:'strict'`),但 queryMergeStatus/saveProtectedBranches 端到端调用未实测;若未来 registry 增加非生成器描述符的额外校验需回查 `validateTypertManifest` 同源逻辑。
3. 非 strict 旁路未深挖:registry 侧手工贡献必须 strict(loader 校验同款),SRC 回退的 `src-json` 弱模式仅限网关运行时推断;示例全部走 strict 最稳。

## 一句话推荐

**最简单可靠的双向通道:host 插件里用一个 `Service + bindTypertRemote + 手工 ctx.typert.register()` 声明两个端点,浏览器直接 `POST /api/gitMergeLock/<method>` 的统一信封调用(需要常显 UI 时再加 dsh.client 目录双面 + `ctx.remote.$mount` 挂成 `remote.gitMergeLock.*`);saveProtectedBranches 这类低频写也可临时借用已有的 git_merge_lock 模型工具通道。**
